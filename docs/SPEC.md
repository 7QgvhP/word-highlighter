# 単語ハイライト VS Code拡張機能 仕様書

## 1. 概要
サイドバーに登録した単語を、エディタ上で文字色・背景色つきで強調表示するVS Code拡張機能。自分用で、vsixファイルを作成して直接インストールして使う(Marketplaceには公開しない)。

## 2. 基本情報
- 拡張機能名: `word-highlighter` / publisher: `7QgvhP`
  - 拡張機能ID(`7QgvhP.word-highlighter`)を変えると保存データが消えるため、確定後は変更しない。
- 表示名(`displayName`): 「単語ハイライト」、`version`: `0.0.1`、`description` は仕様の概要を1文で。
- 言語: TypeScript
- 対象: 最新のVS Code安定版、Windowsのみ。`engines.vscode` には、実装時点の最新安定版のバージョン番号を設定する。
- ライセンス: `UNLICENSED`。READMEは簡易版のみ。
- UI文言・コマンド名・メッセージは日本語固定(多言語対応なし)。
- `settings.json` に拡張機能固有の設定項目は追加しない(`contributes.configuration` は定義しない)。`editor.wordSeparators` の読み取りのみ行う。
- 外部通信なし。テレメトリなし。
- 起動: `activationEvents` に `onStartupFinished` を指定する。サイドバーを開かなくても、VS Code起動後に保存済みの単語がハイライトされること。
- 信頼されていないフォルダ(制限モード)でも動作するよう、`capabilities.untrustedWorkspaces`(`supported: true`)を設定する。設定の書き方は公式ドキュメントで確認すること。

## 3. データモデル
```ts
type WordEntry = {
  id: string;            // 一意ID
  text: string;          // 登録文字列(前後の空白も保持、空文字は不可)
  wholeWord: boolean;    // 単語一致(既定 false)
  regex: boolean;        // 正規表現(既定 false)
  fg: string | null;     // 文字色(#rrggbb、不透明)、null=色なし
  bg: string | null;     // 背景色(#rrggbb、描画時に固定の透明度を適用)、null=色なし
  enabled: boolean;      // 目アイコン(既定 true)
};
type State = {
  schemaVersion: 1;
  words: WordEntry[];     // 並び順 = 優先度(上が優先)
  globalEnabled: boolean; // 拡張機能全体のオン/オフ
  nextColorIndex: number; // 自動割り当て用カウンタ
};
```
- 文字色・背景色とも `#rrggbb` で保存する。背景色の透明度は保存せず、描画時に固定値を適用する(§6)。

## 4. 保存
- 保存先は `context.globalState` の1キー(全プロジェクト共通)。
- 形式バージョン `schemaVersion` を持つ。読み込み時に移行処理を通し、将来項目を追加しても古いデータを読めるようにする。
- **データ破損時**: 起動時の検証に失敗したら通知を出し、そのセッションは**保存を一切行わず**メモリ上で空のまま動かす(保存済みデータを上書きしない)。通知に「データを初期化」ボタンを付け、押すと壊れた生データを別キーに退避してから初期化する。
- 状態の正は拡張機能側(Extension Host)が持つ。Webviewは表示専用とする(§7)。

## 5. マッチング仕様
- 検索は**行単位**。複数行にまたがるマッチは対象外。
- 大文字小文字は**常に区別**(全体で固定、切り替えなし)。
- 通常モード: 文字列リテラルとして検索。
- 正規表現モード: JavaScriptのRegExpを使う。
  - フラグは `g` のみを基本とする。パターンに `\p{...}`、`\P{...}`、`\u{...}` が含まれるときだけ `u` を追加する。`i` は付けない。
  - `u` を常には付けない理由: 不要なエスケープ(`\-` など)でエラーになり、VS Codeの検索窓からコピーした正規表現が弾かれるのを避けるため。
  - 登録時に不正な正規表現: 登録を拒否し、入力欄に赤枠とエラー文を出す。
  - 登録後にトグルを切り替えて不正になった場合: 一覧に警告アイコンを出し、その単語は無効扱い(エラーで拡張機能全体が止まらないようにする)。
- **空文字にマッチするもの**(`^` や `a*` など)は無限ループ防止のためスキップ。
- 単語一致: **VS Code標準の検索の単語一致と同じ振る舞い**にする。
  - `editor.wordSeparators`(ドキュメントの言語に応じた値)を読み取り、マッチの左右の境界を判定する。
  - 左境界OK: 行頭、直前の文字が区切り文字、またはマッチ先頭の文字が区切り文字。右境界も同様。VS Codeの `isValidMatch` 相当の挙動に合わせる。
  - 日本語には区切りがないため、日本語の単語は前後が区切り文字・空白・行頭行末のときだけ一致する(例: 「日本」は「日本語」の中には一致しない)。
  - 正規表現と単語一致が両方ONの場合は、正規表現のマッチ結果に同じ境界判定を適用する。
  - 内部の細かい挙動はVS Codeのバージョンで変わりうるため、実機の検索窓(単語一致ON)と同じ入力で結果を比べて確認する(§10、§11)。
- 重なり: 複数の単語が同じ位置にマッチした場合は**一覧で上にある単語が優先**。
  - 重なった区間は、優先度の高い単語の設定(文字色・背景色とも)だけを使う。優先度の高い単語で「色なし」の項目は、下の単語の色を引き継がず、色なしのまま(エディタ標準の表示)とする。
  - 重ならない部分は、それぞれの単語の色を使う。
  - 自前で範囲を分割し、重ならない範囲を装飾APIに渡す。
- 二重登録のチェックはしない(同じ単語を複数登録してよい。上にあるものが反映される)。
- 正規表現の暴走(極端に遅いパターン)への自動対策は行わない。負荷は表示範囲の限定(§6)で抑える。

## 6. 描画
- `TextEditorDecorationType` を使う。**(文字色, 背景色)の組み合わせごとに共有**し、使われなくなったものは破棄する。
- **背景色の透明度**: 背景色は固定の透明度で描画する。定数 `BG_ALPHA = 0.4`(設定項目にはしない)を `rgba(r, g, b, BG_ALPHA)` として適用する。
  - 目的: 文字色が未設定のとき、ライト・ダークどちらのテーマでも、テーマ標準の文字が読める状態で色味だけを付ける。
  - サイドバーの一覧・パレット・色ボタンのプレビューにも同じ透明度を適用し、エディタ上の見た目と一致させる。
  - 文字色は不透明のまま適用する。
- 両方「色なし」の単語は、装飾を作らない。
- 適用対象は、表示中のすべてのテキストエディタ(ファイル種別・言語で除外しない)。
- コメント・文字列リテラルの判定はしない。
- 装飾は文字色と背景色のみ(太字・下線・枠線・スクロールバーのマークは対象外)。
- 検索範囲は、**表示範囲(visibleRanges)の前後300行程度**。スクロール時に再検索する。
- 再描画のトリガーと待ち時間:
  - ドキュメント編集: 150msのデバウンス
  - スクロール、アクティブエディタ・表示エディタの変更: 150msのデバウンス
  - 登録単語の変更や全体オン/オフの切り替え: 即時
- 全体オフ時は、すべての装飾を解除する。
- 想定する負荷: 通常のソース(数千行)で単語20〜50個ならほぼ体感できない。巨大ファイルは表示範囲の限定で負荷をほぼ一定にする。

## 7. サイドバー(Webviewビュー)
- 専用のActivity Barアイコン(仮のモノクロSVGを作成して含める。後から差し替え可能な構成にする)。ビュー名は「登録単語」。
- 見た目はVS Codeのテーマ用CSS変数に追従する。CSPとnonceを設定し、外部リソースは読み込まない。
- **状態の扱い**: Webviewは非表示にすると破棄されるため、状態を持たせない。表示されるたび(初回表示・再表示)に、拡張機能側が現在の状態を送って描画する。操作はWebviewからメッセージで拡張機能側に送り、拡張機能側が状態を更新して保存し、結果をWebviewに送り返す。
- **タイトルバー**: ビューのタイトルバー(`view/title`)に、**全体オン/オフの切り替えボタン**を置く。オン/オフの状態がアイコンの見た目でわかること。
- **全体オフの表示**: 全体オフのとき、一覧の上に「全体オフ(ハイライトは無効です)」の表示を出す。
- **入力欄**: テキスト入力 + 登録ボタン(Enterでも登録)。トグルは置かない。登録時は単語一致OFF・正規表現OFF。空文字は登録不可。
- **新規登録の位置**: 一覧の**末尾**に追加(既存の優先度を変えない)。色は背景色のみで、背景パレットを `nextColorIndex` で順番に循環して割り当てる。文字色は「色なし」。
- **一覧の1行**: 並べ替えハンドル / 目アイコン / 単語 / 単語一致ボタン / 正規表現ボタン / 文字色ボタン / 背景色ボタン / 削除ボタン。
  - 単語のテキスト自体を設定した文字色・背景色で表示して、プレビューを兼ねる(背景色は§6の透明度を適用)。
  - 無効(目アイコンOFF)の行は薄く表示。不正な正規表現の行は警告アイコンを表示。
  - 単語一致・正規表現ボタンは、VS Codeの検索窓のようなトグルの見た目にする。
  - 行のクリックによるエディタ上のジャンプはなし。
- **並べ替え**: ドラッグ&ドロップ(手動)。並び順がそのまま優先度になる。
- **色ボタン**: クリックでパレットを表示する。
  - 文字色・背景色とも16色程度。テーマ別の切り替えはない。背景色は§6の透明度で描画されることを前提に選ぶ。
  - 「色なし」の選択肢を設ける(文字色だけ・背景色だけの設定を許可)。
  - 「カスタム色」はOS標準のカラーピッカー(`<input type="color">`)をパレットと併用する形。カスタム色の背景色にも同じ透明度を適用する。
  - 最近使った色の機能は作らない。
  - 実装の最初の段階で、`<input type="color">` がVS CodeのWebview内で期待どおり開き、選んだ色を受け取れることを確認する。動かない場合は、代替案を提示して相談する。
- **削除**: 単語1つは確認なしで削除。ヘッダーに「すべて削除」ボタン(確認ダイアログつき)。削除した単語はエディタ標準の表示に戻る。
- 登録数の上限は設けない。

## 8. コマンド・メニュー
- 「選択テキストを登録」: エディタの右クリックメニューとコマンドパレットから実行できる。
  - 選択がないときは**カーソル位置の単語**を登録対象にする。取得できない場合は通知のみ。
  - 複数行にまたがる選択は拒否して通知する。
  - 登録時の設定は入力欄からの登録と同じ(単語一致OFF・正規表現OFF、背景色を自動割り当て)。
  - ショートカットキーは既定では割り当てない(ユーザーがキーボードショートカット設定から自分で割り当てる)。
- 「全体のオン/オフ切り替え」: コマンドパレットと、サイドバーのタイトルバーのボタンから実行できる。状態は再起動後も保持する。
- 「すべての単語を削除」: コマンドパレットから実行(確認ダイアログつき)。
- 各単語の無効化(目アイコン)の状態も再起動後も保持する。
- ステータスバーへの表示は行わない。

## 9. 対象外にしたもの
データのエクスポート/インポート、設定同期、コメント・文字列内の判定、一覧クリックでのジャンプ、テーマ別の色切り替え、単語数の上限、二重登録のチェック、`settings.json` の設定項目、多言語対応、1行あたりの検索上限、スクロールバーのマーク、最近使った色、太字・下線などの装飾、キーボードショートカットの既定割り当て、ステータスバーの表示、入力欄のトグル、正規表現の暴走対策(自動無効化)、重なったときの「色なし」項目の引き継ぎ。

## 10. 開発環境
- npm、esbuild(バンドル)、ESLint。
- 一致判定ロジックの単体テストは vitest で書く。対象は、通常・正規表現・単語一致・日本語・空マッチのスキップ・重なりの分割・正規表現フラグ(`\-` を含むパターンが受け付けられること、`\p{...}` を含むときだけ `u` が付くこと)。
- 単語一致は、VS Codeの検索窓(単語一致ON)と同じ入力で結果を比べて期待値を決める。最低限、次のケースを含める。
  - `foo` と `foo_bar`、`foobar`、`foo-bar`、`foo.bar`
  - 区切り文字で始まる・終わる単語(`.foo`、`foo.`)
  - 日本語(`日本` と `日本語`、前後が空白や句読点の場合)
  - 正規表現と単語一致が両方ONの場合
- `npm run package` でvsixを生成できる(`@vscode/vsce`、`.vscodeignore` を整備)。
- 推奨するファイル構成: `extension.ts`(起動・コマンド登録)、`store.ts`(保存・読み込み・検証・移行)、`matcher.ts`(マッチ判定・重なり解決)、`decorator.ts`(装飾の適用・共有・破棄)、`sidebar`(Webviewビューのプロバイダと画面)。
- Git運用は別ドキュメントのルールに従う。

## 11. 受け入れ基準
- 単語を登録すると、開いているすべてのエディタで一致箇所に背景色が付く。
- 背景色が付いても、ライト・ダークどちらのテーマでも、文字色なしの文字が読める。
- 文字色・背景色をパレットから変更でき、「色なし」にもできる。カスタム色も選べる。
- 単語を削除すると、そのハイライトが消える。
- 一覧をドラッグで並べ替えると、重なったときの優先順位が変わる。重なった区間では上の単語の設定だけが使われる。
- 単語一致をONにすると、VS Codeの検索の単語一致と同じ結果になる(`foo` は `foo_bar` に一致しない、日本語は前後が区切りのときだけ一致する、など)。
- 正規表現で `\-` のような不要なエスケープを含むパターンも登録できる。不正な正規表現は登録できず、登録後に不正になった場合も拡張機能が止まらない。
- サイドバーのタイトルバーのボタンで全体オン/オフを切り替えられ、オフのときは一覧の上に表示が出てハイライトが消える。
- VS Codeを再起動しても、登録内容・並び順・無効化の状態・全体オン/オフが保持される。
- VS Codeを起動した直後、サイドバーを開かなくても、保存済みの単語がハイライトされる。
- 保存データが壊れていても、保存済みデータを上書きしない。
- settings.json が一切書き換わらない。
- `npm run package` でvsixが作成でき、インストールして動作する。
