# word-highlighter VS Code拡張機能 仕様書

この仕様書は、実装（v1.0.0）に合わせて書き直したもの。

## 1. 概要
サイドバーに登録した単語を、エディタ上で文字色・背景色つきで強調表示するVS Code拡張機能。自分用で、vsixファイルを作成して直接インストールして使う(Marketplaceには公開しない)。vsixは、GitHub Releasesに添付して配布する(§10)。

## 2. 基本情報
- 拡張機能名(`name`): `word-highlighter` / publisher: `7QgvhP`
  - 拡張機能ID(`7QgvhP.word-highlighter`)を変えると保存データが消えるため、変更しない。
- 表示名(`displayName`): `word-highlighter`(他の拡張機能にそろえて英語にする)。`description` は「サイドバーに登録した単語を、エディタ上で文字色・背景色つきで強調表示します。」。
- バージョンは `1.0.0` から始める(Git運用のルールに従う)。
- 言語: TypeScript
- 対象: 最新のVS Code安定版、Windowsのみ。`engines.vscode` は `^1.141.0`(実装時点の最新安定版)。
- ライセンス: `UNLICENSED`(LICENSEファイルは置かない)。READMEは簡易版のみ。
- UI文言・コマンド名・メッセージは日本語固定(多言語対応なし)。ただし、拡張機能の名前を表す箇所(アクティビティバーの名前、コマンドの分類、通知の接頭辞)は `word-highlighter` とする。
- `settings.json` に拡張機能固有の設定項目は追加しない(`contributes.configuration` は定義しない)。`editor.wordSeparators` の読み取りのみ行う。
- 外部通信なし。テレメトリなし。実行時の依存ライブラリなし。
- 起動: `activationEvents` に `onStartupFinished` を指定する。サイドバーを開かなくても、VS Code起動後に保存済みの単語がハイライトされる。
- 信頼されていないフォルダ(制限モード)でも動作するよう、`capabilities.untrustedWorkspaces` に `{ "supported": true }` を設定する。

## 3. データモデル
```ts
type WordEntry = {
  id: string;            // 一意ID(crypto.randomUUID)
  text: string;          // 登録文字列(前後の空白も保持、空文字は不可)
  wholeWord: boolean;    // 単語一致(既定 false)
  regex: boolean;        // 正規表現(既定 false)
  fg: string | null;     // 文字色(#rrggbb、不透明)、null=色なし
  bg: string | null;     // 背景色(#rrggbb、描画時に固定の透明度を適用)、null=色なし
  enabled: boolean;      // 目アイコン(既定 true)
};
type State = {
  schemaVersion: 1;
  words: WordEntry[];     // 並び順 = 優先度(上が優先)
  globalEnabled: boolean; // 拡張機能全体のオン/オフ(既定 true)
  nextColorIndex: number; // 自動割り当て用カウンタ(既定 0)
};
```
- 文字色・背景色とも、小文字の `#rrggbb` にそろえて保存する。背景色の透明度は保存せず、描画時に固定値を適用する(§6)。

## 4. 保存
- 保存先は `context.globalState` のキー `wordHighlighter.state`(全プロジェクト共通)。
- 形式バージョン `schemaVersion` を持つ。読み込み時に移行処理を通し、将来項目を追加しても古いデータを読めるようにする(現在は `1` のみで、移行処理はない)。
- 読み込み時の検証: 次のいずれかに当てはまる場合は、データ破損とみなす。
  - オブジェクトでない、`schemaVersion` がない、`schemaVersion` が現在より新しい(新しい版の拡張機能で保存されたデータ)、または1未満
  - `words` が配列でない、`globalEnabled` が真偽値でない、`nextColorIndex` が0以上の整数でない
  - 単語の `id` が空・重複、`text` が空、`wholeWord`/`regex`/`enabled` が真偽値でない、`fg`/`bg` が `null` でも `#rrggbb` でもない
  - 未保存(値がない)の場合は、破損ではなく初期状態として扱う。
- **データ破損時**: エラー通知を出し、そのセッションは**保存を一切行わず**メモリ上で空のまま動かす(保存済みデータを上書きしない)。サイドバーにも「保存データを読み込めなかったため、このセッションでは変更を保存しません。」と表示する。
  - 通知に「データを初期化」ボタンを付ける。押すと確認ダイアログ(モーダル)を出し、「初期化」を選ぶと、壊れた生データを `wordHighlighter.state.corrupted.<ISO 8601の日時>` に退避してから初期化して保存する。退避先のキーは通知で知らせる。
- 状態の正は拡張機能側(Extension Host)が持つ。Webviewは表示専用とする(§7)。

## 5. マッチング仕様
- 検索は**行単位**。複数行にまたがるマッチは対象外。
- 大文字小文字は**常に区別**(全体で固定、切り替えなし)。
- 1つの単語の一致は、重ならないように行頭から順に探す。一致した後は、その一致の末尾から次を探す(例: `aa` は `aaaa` の0文字目と2文字目に一致し、`aaa` では0文字目だけに一致する)。VS Codeの検索と同じ。
- 通常モード: 文字列リテラルとして検索。
- 正規表現モード: JavaScriptのRegExpを使う。
  - フラグは `g` のみを基本とする。パターンに `\p{...}`、`\P{...}`、`\u{...}` が含まれるときだけ `u` を追加する。`i` は付けない。`\\p{` のように、バックスラッシュ自体がエスケープされている場合は含まないとみなす。
  - `u` を常には付けない理由: 不要なエスケープ(`\-` など)でエラーになり、VS Codeの検索窓からコピーした正規表現が弾かれるのを避けるため。
  - 登録は常に正規表現OFFで行うため、登録時に正規表現の検証はしない。
  - 登録後にトグルを切り替えて不正になった場合: 一覧に警告アイコン(エラー文をツールチップに表示)を出し、その単語は無効扱い(位置も確保しない)。エラーで拡張機能全体が止まらないようにする。
- **空文字への一致**(`^`、`x*` が一致しない位置、先読みだけのパターンなど)は、無限ループ防止のためスキップし、1文字(サロゲートペアは2コード単位)進めて検索を続ける。空でない一致はハイライトする(例: `a*` は `baab` の `aa` に一致する)。
- 単語一致: **VS Code標準の検索の単語一致と同じ振る舞い**にする(VS Codeの `isValidMatch` と同じ規則)。
  - `editor.wordSeparators`(ドキュメントの言語に応じた値)を読み取り、マッチの左右の境界を判定する。半角スペースとタブは、区切り文字とは別の「空白」として、境界の文字に含める。判定はUTF-16のコード単位で行う。
  - 左境界OK: 行頭、直前の文字が区切り文字・空白、またはマッチ先頭の文字が区切り文字・空白。
  - 右境界OK: 行末、直後の文字が区切り文字・空白、またはマッチ末尾の文字が区切り文字・空白。
  - 境界を満たさない一致は捨て、その一致の末尾から次を探す。
  - 日本語には区切りがないため、日本語の単語は前後が区切り文字・空白・行頭行末のときだけ一致する(例: 「日本」は「日本語」の中には一致しない)。
  - 既定の `editor.wordSeparators` には、「、」「。」や全角空白が含まれない。そのため、「日本、」「。日本」「　日本　」の「日本」には一致しない(VS Codeの検索窓と同じ)。
  - 正規表現と単語一致が両方ONの場合は、正規表現のマッチ結果に同じ境界判定を適用する。
  - 内部の細かい挙動はVS Codeのバージョンで変わりうるため、実機の検索窓(単語一致ON)と同じ入力で結果を比べて確認する(`samples/word-match.txt`、§10)。
- 重なり: 複数の単語が同じ位置にマッチした場合は**一覧で上にある単語が優先**。
  - 行ごとに、優先度の高い単語から順に文字の位置を確保する。確保した位置には、確保した単語の設定(文字色・背景色とも)だけを使う。優先度の高い単語で「色なし」の項目は、下の単語の色を引き継がず、色なしのまま(エディタ標準の表示)とする。両方とも色なしの単語も、位置は確保する。
  - 重ならない部分は、それぞれの単語の色を使う。
  - 同じ色の組み合わせが続く区間は1つにまとめ、重ならない範囲を装飾APIに渡す。
- 無効(目アイコンOFF)の単語は、位置を確保しない。
- 二重登録のチェックはしない(同じ単語を複数登録してよい。上にあるものが反映される)。
- 正規表現の暴走(極端に遅いパターン)への自動対策は行わない。負荷は表示範囲の限定(§6)で抑える。

## 6. 描画
- `TextEditorDecorationType` を使う。**(文字色, 背景色)の組み合わせごとに共有**し、表示中のどのエディタでも使われなくなったものは破棄する。`rangeBehavior` は `ClosedClosed`。
- **背景色の透明度**: 背景色は固定の透明度で描画する。定数 `BG_ALPHA = 0.4`(設定項目にはしない)を `rgba(r, g, b, BG_ALPHA)` として適用する。
  - 目的: 文字色が未設定のとき、ライト・ダークどちらのテーマでも、テーマ標準の文字が読める状態で色味だけを付ける。
  - サイドバーの一覧・パレット・色ボタンのプレビューにも同じ透明度を適用し、エディタ上の見た目と一致させる。
  - 文字色は不透明のまま適用する。
- 両方「色なし」の区間は、装飾を作らない。
- 適用対象は、表示中のすべてのテキストエディタ(ファイル種別・言語で除外しない)。
- コメント・文字列リテラルの判定はしない。
- 装飾は文字色と背景色のみ(太字・下線・枠線・スクロールバーのマークは対象外)。
- 検索範囲は、**表示範囲(visibleRanges)の前後300行**。表示範囲が複数ある場合(折りたたみなど)は、重なる・隣接する範囲をまとめる。スクロール時に再検索する。
- 再描画のトリガーと待ち時間:
  - ドキュメント編集(表示中のエディタのドキュメントのみ): 150msのデバウンス
  - スクロール、アクティブエディタ・表示エディタの変更、`editor.wordSeparators` の変更: 150msのデバウンス
  - 登録単語の変更や全体オン/オフの切り替え: 即時
  - 再描画は、表示中のすべてのエディタに対して行う。
- 全体オフ時、または有効な単語がないときは、すべての装飾を解除する。
- 想定する負荷: 通常のソース(数千行)で単語20〜50個ならほぼ体感できない。巨大ファイルは表示範囲の限定で負荷をほぼ一定にする。

## 7. サイドバー(Webviewビュー)
- 専用のActivity Barアイコン(仮のモノクロSVG `media/icon.svg`。ファイルの置き換えで差し替えられる)。アクティビティバーの名前は `word-highlighter`、ビュー名は「登録単語」。
- 見た目はVS Codeのテーマ用CSS変数に追従する。CSP(`default-src 'none'`、スタイルは拡張機能内のCSSファイルのみ、スクリプトはnonce付きのもののみ)を設定し、外部リソースは読み込まない。色などの動的なスタイルは、スクリプトからCSSOMで設定する。
- **デザイン**: 同時に画面に出したときに統一感が出るよう、c-function-analyzerの解析結果画面にそろえる。
  - 配色は彩度を抑え、文字は11〜12px、枠は細い線と小さい角丸(3px)。
  - 単語一覧は、細い枠線のセクション(見出し「単語一覧」)にまとめる。分類の色分けがないため、左のアクセント線は付けない。
  - ボタンは控えめな色で、マウスを乗せたときに文字色が濃くなる。単語・入力欄は、エディタのフォント(等幅)で表示する。
- **状態の扱い**: Webviewは非表示にすると破棄されるため、状態を持たせない。Webviewは読み込みが終わると `ready` を送り、拡張機能側が現在の状態を送って描画する(表示状態が変わったときも送る)。操作はWebviewからメッセージで拡張機能側に送り、拡張機能側が状態を更新して保存し、結果をWebviewに送り返す。
- **タイトルバー**: ビューのタイトルバー(`view/title`)に、**全体オン/オフの切り替えボタン**を置く。オンのときは目のアイコン(`eye`)、オフのときは閉じた目のアイコン(`eye-closed`)を、コンテキストキー `wordHighlighter.globalEnabled` で切り替えて表示する。
- **全体オフの表示**: 全体オフのとき、入力欄の上に「全体オフ(ハイライトは無効です)」の表示を出す。
- **入力欄**: テキスト入力 + 登録ボタン(Enterでも登録。日本語の変換中のEnterは除く)。トグルは置かない。登録時は単語一致OFF・正規表現OFF。空文字は登録不可で、入力欄に赤枠とエラー文を出す(入力し直すと消える)。登録に成功すると入力欄を空にする。
- **新規登録の位置**: 一覧の**末尾**に追加(既存の優先度を変えない)。色は背景色のみで、背景パレットを `nextColorIndex` で順番に循環して割り当てる。文字色は「色なし」。
- **単語一覧の見出し**: 「単語一覧」、登録数、「すべて削除」ボタン(登録がないときは無効)。登録がないときは「単語が登録されていません。」と表示する。
- **一覧の1行**: 並べ替えハンドル / 目アイコン / 単語 / (不正な正規表現の警告アイコン) / 単語一致ボタン / 正規表現ボタン / 文字色ボタン / 背景色ボタン / 削除ボタン。
  - 単語のテキスト自体を設定した文字色・背景色で表示して、プレビューを兼ねる(背景色は§6の透明度を適用)。色は文字の部分にだけ付け、欄の余白には付けない(エディタ上の見た目にそろえる)。長い単語は末尾を省略し、全文はツールチップで表示する。
  - 無効(目アイコンOFF)の行は薄く表示。不正な正規表現の行は警告アイコンを表示。
  - 単語一致(`ab` に下線)・正規表現(`.*`)ボタンは、VS Codeの検索窓のようなトグルの見た目(`inputOption` の配色)にする。
  - 色ボタンは、文字色は「A」をその色で、背景色は色見本を透明度付きで表示する。色なしは斜線で表す。
  - 削除ボタンは、行にマウスを乗せたときに濃く表示する。
  - 行のクリックによるエディタ上のジャンプはなし。
- **並べ替え**: ドラッグ&ドロップ(手動)。並べ替えハンドルをつかんだときだけドラッグでき、ドロップ位置を線で示す。並び順がそのまま優先度になる。
- **色ボタン**: クリックでパレットを表示する(同じボタンをもう一度押す、パレットの外をクリックする、Escキーで閉じる)。
  - 文字色・背景色とも16色。テーマ別の切り替えはない。背景色は§6の透明度で描画されることを前提に選ぶ。ダークテーマの黒い背景でも目立つように、文字色・背景色とも明るい色にする。現在の色には選択中の枠を付ける。
    - 背景色(割り当て順): `#fff176` 黄、`#4dd0e1` シアン、`#f06292` ピンク、`#81c784` 緑、`#ffb74d` オレンジ、`#64b5f6` 青、`#ba68c8` 紫、`#dce775` ライム、`#e57373` 赤、`#4db6ac` ティール、`#7986cb` 藍、`#aed581` 黄緑、`#4fc3f7` 水色、`#9575cd` 濃い紫、`#a1887f` 茶、`#e0e0e0` 灰
    - 文字色: `#ff8a80` 赤、`#ffb74d` オレンジ、`#fff176` 黄、`#81c784` 緑、`#4db6ac` ティール、`#64b5f6` 青、`#9fa8da` 藍、`#ce93d8` 紫、`#f48fb1` ピンク、`#bcaaa4` 茶、`#ff5252` 明るい赤、`#ffd740` 明るい黄、`#69f0ae` 明るい緑、`#40c4ff` 明るい青、`#ffffff` 白、`#ea80fc` 明るい紫
  - パレットの下に「色なし」と「カスタム」のボタンを置く(文字色だけ・背景色だけの設定を許可)。
  - 「カスタム」はOS標準のカラーピッカー(`<input type="color">`)を開き、選び終えた時点(`change`)で反映する。カスタム色の背景色にも同じ透明度を適用する。パレットにない色を使っているときは、「カスタム」に選択中の枠を付ける。
  - 最近使った色の機能は作らない。
- **削除**: 単語1つは確認なしで削除。「すべて削除」は、VS Codeの確認ダイアログ(モーダル)を出してから削除する。削除した単語はエディタ標準の表示に戻る。
- 登録数の上限は設けない。

## 8. コマンド・メニュー
コマンドの分類(コマンドパレットでの接頭辞)は `word-highlighter`。
- 「選択テキストを登録」(`wordHighlighter.addSelection`): エディタの右クリックメニューとコマンドパレットから実行できる。
  - 選択がないときは**カーソル位置の単語**を登録対象にする。取得できない場合は通知のみ。
  - 複数行にまたがる選択は拒否して通知する。複数の選択があるときは、主となる選択を使う。
  - 登録時の設定は入力欄からの登録と同じ(単語一致OFF・正規表現OFF、背景色を自動割り当て)。
  - ショートカットキーは既定では割り当てない(ユーザーがキーボードショートカット設定から自分で割り当てる)。
- 「全体のオン/オフ切り替え」(`wordHighlighter.toggleGlobal`): コマンドパレットから実行できる。サイドバーのタイトルバーのボタンは、オン/オフの状態に応じた専用のコマンド(`wordHighlighter.turnOff` / `wordHighlighter.turnOn`。コマンドパレットには出さない)で切り替える。状態は再起動後も保持する。
- 「すべての単語を削除」(`wordHighlighter.deleteAll`): コマンドパレットから実行(確認ダイアログつき)。登録がないときは、その旨を通知する。
- 各単語の無効化(目アイコン)の状態も再起動後も保持する。
- ステータスバーへの表示は行わない。

## 9. 対象外にしたもの
データのエクスポート/インポート、設定同期、コメント・文字列内の判定、一覧クリックでのジャンプ、テーマ別の色切り替え、単語数の上限、二重登録のチェック、`settings.json` の設定項目、多言語対応、1行あたりの検索上限、スクロールバーのマーク、最近使った色、太字・下線などの装飾、キーボードショートカットの既定割り当て、ステータスバーの表示、入力欄のトグル、正規表現の暴走対策(自動無効化)、重なったときの「色なし」項目の引き継ぎ、登録した単語の文字列の編集。

## 10. 開発環境
- npm、esbuild(バンドル。`dist/extension.js` に1ファイルにまとめる)、TypeScript(`tsc --noEmit` で型チェックのみ)、ESLint(`eslint.config.mjs`、`typescript-eslint`)。
- `@types/vscode` は、`engines.vscode` より新しくならないよう版を固定する(vsceがエラーにするため)。
- npmスクリプト:
  - `npm test`: lint、型チェック、テストのビルド(esbuildで `dist-test/` に出力)、`node --test` の実行
  - `npm run compile`: ビルド
  - `npm run package`: vsixの作成(`vsce package --skip-license`。LICENSEファイルを置かないため)
- テストは `node:test` で書き、VS Codeを起動せずに実行する。vscodeモジュールに依存しない部分(`matcher.ts`、`store.ts`、`sidebar/html.ts`)を対象にする。
  - マッチ判定: 通常・正規表現・単語一致・日本語・空マッチのスキップ・重なりの分割・正規表現フラグ(`\-` を含むパターンが受け付けられること、`\p{...}` などを含むときだけ `u` が付くこと)・検索範囲。
  - 保存: 検証(破損の検出)、状態の操作、破損時に保存しないこと、初期化時の退避。
  - Webviewの HTML: CSPとnonce、外部リソースを読み込まないこと。
  - テスト名の末尾の `(vX.Y.Z)` は、その挙動が確定したバージョンを表す。
- 単語一致は、VS Codeの検索窓(単語一致ON)と同じ入力で結果を比べて期待値を決める。最低限、次のケースを含める(確認用の入力は `samples/word-match.txt`。vsixには含めない)。
  - `foo` と `foo_bar`、`foobar`、`foo-bar`、`foo.bar`
  - 区切り文字で始まる・終わる単語(`.foo`、`foo.`)
  - 日本語(`日本` と `日本語`、前後が空白や句読点の場合)
  - 正規表現と単語一致が両方ONの場合
- vscodeに依存する部分(`decorator.ts`、`extension.ts`、`sidebar/provider.ts`、`media/`)は、実機で確認する。
- ファイル構成:
  - `src/extension.ts`(起動・コマンド登録・各部品の接続)、`src/store.ts`(保存・読み込み・検証・移行と、状態を変える操作)、`src/matcher.ts`(マッチ判定・単語境界・重なり解決・検索範囲)、`src/decorator.ts`(装飾の適用・共有・破棄)、`src/colors.ts`(パレットと透明度)、`src/types.ts`(型定義)、`src/sidebar/`(Webviewビューのプロバイダ `provider.ts` と HTML `html.ts`)
  - `media/`(Webviewの画面 `sidebar.js`・`sidebar.css` と、アイコン `icon.svg`)
  - `test/`(テスト)、`samples/`(確認用の入力)、`docs/`(本書)
- `.vscodeignore` で、`src/`、`test/`、`docs/`、`samples/`、`.github/`、`CLAUDE.md` など、配布物に不要なファイルを除外する。
- リリース: `v` で始まるタグをpushすると、GitHub Actions(`.github/workflows/release.yml`)が、タグと `package.json` のバージョンの一致確認、テスト、vsixの作成、GitHub Releasesへの添付を行う。
- Git運用は別ドキュメントのルールに従う。

## 11. 受け入れ基準
- 単語を登録すると、開いているすべてのエディタで一致箇所に背景色が付く。
- 背景色が付いても、ライト・ダークどちらのテーマでも、文字色なしの文字が読める。
- 文字色・背景色をパレットから変更でき、「色なし」にもできる。カスタム色も選べる。
- サイドバーの単語のプレビューは、文字の部分にだけ背景色が付く(サイドバーの幅を広げても、背景色は広がらない)。
- 単語を削除すると、そのハイライトが消える。
- 一覧をドラッグで並べ替えると、重なったときの優先順位が変わる。重なった区間では上の単語の設定だけが使われる。
- 単語一致をONにすると、VS Codeの検索の単語一致と同じ結果になる(`foo` は `foo_bar` に一致しない、日本語は前後が区切りのときだけ一致する、など)。
- 正規表現で `\-` のような不要なエスケープを含むパターンも使える。登録後に不正な正規表現になっても、警告アイコンが出るだけで拡張機能は止まらない。
- サイドバーのタイトルバーのボタンで全体オン/オフを切り替えられ、オフのときは入力欄の上に表示が出てハイライトが消える。
- VS Codeを再起動しても、登録内容・並び順・無効化の状態・全体オン/オフが保持される。
- VS Codeを起動した直後、サイドバーを開かなくても、保存済みの単語がハイライトされる。
- 保存データが壊れていても、保存済みデータを上書きしない。
- settings.json が一切書き換わらない。
- `npm run package` でvsixが作成でき、インストールして動作する。
